# Build and release (everything runs on GitHub)

## 0. One-time settings in the GitHub repo
1. **Settings > Pages**: Source = "Deploy from a branch", Branch = `main`, folder = `/docs`. Your privacy policy will be live at `https://ahsanz89.github.io/BrainRush-AI/privacy-policy.html`.
2. Edit `src/config.ts`: set `developerName` and `supportEmail`, then run `npm run store:build` (or ask Claude) and commit. These appear in the policy pages and the app's Help screen.

## 1. Try the app on a phone (no secrets needed)
Actions tab > **Android build** > latest run > artifact **BrainRush-AI-test-apk**. Unzip, copy `BrainRush-AI-test.apk` to an Android phone and install (allow "install unknown apps" for your file manager). This is a full, self-contained build signed with a debug key. It is for testing only and cannot be uploaded to Google Play.

## 2. Create your upload key (once, keep it safe)
You need any computer with Java (JDK 17+).
```bash
keytool -genkeypair -v -storetype PKCS12 -keystore upload.jks -alias upload -keyalg RSA -keysize 2048 -validity 10000
base64 -w0 upload.jks > upload.jks.b64     # macOS: base64 -i upload.jks -o upload.jks.b64
```
Then in GitHub: **Settings > Secrets and variables > Actions > New repository secret**, create four secrets:

| Secret | Value |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | the contents of `upload.jks.b64` |
| `ANDROID_KEYSTORE_PASSWORD` | the keystore password you typed |
| `ANDROID_KEY_ALIAS` | `upload` |
| `ANDROID_KEY_PASSWORD` | the key password you typed |

**Back up `upload.jks` and both passwords somewhere safe outside GitHub. Never commit them.** With Play App Signing (recommended, default for new apps) Google holds the final app-signing key, so a lost upload key can be reset through Play support, but it is a hassle.

## 3. Build the signed release
Actions > **Android build** > **Run workflow** > tick **release** > Run. The job fails with a clear message if any secret is missing, and fails if the output is signed with the debug key.
Download artifact **BrainRush-AI-release**: `BrainRush-AI-release.aab` (upload this to Google Play), `BrainRush-AI-release.apk`, `SHA256SUMS.txt`.
The repository is public, so build artifacts are visible to anyone who is signed in to GitHub. They contain no secrets (the signing key never leaves the runner). If you prefer them private, make the repository private.

## 4. Every later release
1. Increase `version` and `android.versionCode` in `app.json` (versionCode must go up every upload).
2. Update `store/listing/en-US/release-notes.txt`.
3. Run the release workflow again and upload the new AAB.

## Build details
- Native project is generated by `expo prebuild` on every build (never committed). Target SDK 36 (Play requirement), compile SDK 37 (required by Expo SDK 58 libraries), min SDK 24 are set in `app.json` via `expo-build-properties`.
- `plugins/withReleaseSigning.js` makes Gradle sign with your upload key when the secrets are present.
- Only GitHub's official actions are used (`checkout`, `setup-node`, `setup-java`, `upload-artifact`).
- The first run of each job may need small fixes (Gradle/SDK version drift). If a run fails, open the run log and send it to Claude.
