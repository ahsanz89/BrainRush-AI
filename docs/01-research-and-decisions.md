# BrainRush AI — Phase 1–2: Research, Decisions, PRD (v0.1)

Status: draft for build. Date: 2026-11-24.

## 1. Environment finding (drives the stack)
- Workspace has Java 17+, Gradle, Node 22, Python 3.13. No Android SDK.
- Egress allowlist blocks dl.google.com, maven.google.com, Maven Central, services.gradle.org, plugins.gradle.org. npm and PyPI work.
- Consequence: native Kotlin cannot be compiled or tested here.
- Decision: React Native + Expo (TypeScript). Logic is unit-tested here with Jest. APK/AAB are compiled by EAS cloud builds (owner's Expo account needed).
- Not verified yet: whether EAS free-tier build quota is enough; owner to confirm account.

## 2. Market snapshot
Competitors: Lumosity, Elevate, Peak, NeuroNation, CogniFit, BrainHQ, MindPal, Impulse.
- Lumosity/Elevate/Peak: freemium + subscription, game-per-skill, fixed "science-based" claims.
- Gaps for BrainRush: (a) free, ad-supported, no paywall; (b) adaptive daily sessions mixing quiz + puzzles; (c) AI-written explanations that are always backed by validated answer keys; (d) no unverifiable "improves IQ" claims.
- Marketing rule: do NOT claim medical or cognitive-improvement outcomes. Say "exercise", "practice", "fun".

## 3. Key decisions (with reasoning)
| Area | Decision | Why | Alternative |
|---|---|---|---|
| App | Expo SDK (current) + TypeScript + expo-router | Buildable/testable from this sandbox; EAS builds AAB | Kotlin/Compose (not buildable here) |
| Local DB | expo-sqlite | Offline play, simple | Room (native only) |
| Backend | Supabase (Postgres + Auth + RLS + Edge Functions) | Free tier, SQL, server-side rules | Firebase (weaker for relational rules) |
| AI | Provider-agnostic Edge Function; LLM only for explanations, hints, variations; batch/offline generation into a review queue | Cost control, no runtime dependence | Live generation per play (costly, unreliable) |
| Game logic | Deterministic TS modules in `packages/engine` (scoring, XP, streaks, validators) | Testable, never AI | — |
| Ads | AdMob via react-native-google-mobile-ads; test IDs only until owner supplies real ones | Policy-compliant, standard | — |
| Auth | Supabase Auth email + guest (anonymous) mode | Low friction | — |
| Analytics/crash | Firebase Crashlytics/Analytics optional, consent-gated; decide at Phase 8 | Privacy | Sentry free tier |

## 6. MVP scope
Included: onboarding, guest + email auth, home dashboard, 10 categories with 5 distinct game mechanics (MCQ quiz, memory grid, math sprint with generated problems, pattern match, reaction/attention), Daily Challenge, Quick, Timed, Practice, Mixed Workout, results + explanations, XP/levels/streaks/achievements, profile/progress, settings, privacy/terms, AdMob (banner on non-play screens, interstitial at result breaks with cap, rewarded for hint), account deletion.
Deferred: leaderboards, localization, subscriptions, social.

## 7. PRD essentials
- Problem: casual users want short, fun, trustworthy daily mental exercise without subscriptions.
- Personas: Student (exam prep, 15 min), Professional (5-min break), Casual puzzler.
- Non-functional: cold start <3s mid-range device, offline play from cached packs, WCAG AA contrast, 48dp touch targets, back-navigation correct.
- Integrity: server computes XP from submitted session; caps per day per category; rejects impossible times.
- Acceptance: all engine unit tests pass; release AAB installs and runs a full session on a device/emulator (owner or EAS); no production ad IDs in repo.

## 9. REVISION (owner directive 2026-11-24): GitHub-only, no third-party services
Owner requires all code, content and Play Store resources to live in this GitHub repo with no third-party service dependencies. This supersedes the Supabase / EAS / runtime-AI choices in section 3.

| Area | New decision |
|---|---|
| Builds (APK/AAB) | GitHub Actions (`.github/workflows/android.yml`): `expo prebuild` + Gradle on GitHub runners; artifacts attached to the run/Release. Replaces EAS. |
| Signing | Upload keystore generated by the workflow's helper script, stored as GitHub Actions Secrets. Never committed. |
| Accounts/backend | None. Offline-first, on-device profile (SQLite/AsyncStorage). XP/streak/anti-abuse rules run in the shared engine on-device. Leaderboards and cloud sync deferred (they need a server). |
| Content updates without app release | Versioned JSON content packs in `/content`, published via GitHub Pages; app fetches optional updates, bundled pack is the fallback. |
| AI | Used offline at authoring time only; output must pass `validateQuestion` and deterministic generators before being committed. No runtime AI calls, no API keys in app. |
| Play Store resources | `/store`: listing copy, privacy policy, Data Safety answers, content-rating answers, screenshots, feature graphic, checklists. |
| Ads | AdMob is inherently a Google service. Included behind a build flag, OFF by default, test IDs only. Owner to decide whether to ship ads; if not, app is ad-free. |
| Analytics/crash | None by default (privacy-first, simpler Data Safety form). |

Trade-off accepted: no cross-device sync, no global leaderboard, anti-cheat is best-effort on-device.
